# GitHub + Hugo 시스템에 대하여

# SSG란?

**SSG**는 **Static Site Generator (정적 사이트 생성기)** 의 약자입니다.

컴퓨터 공학적으로 한 문장으로 정의하자면  **"웹사이트를 위한 컴파일러(Compiler)"** 입니다.

---

### 1. 역사적 뿌리: "돌고 돌아 다시 순정으로"

웹의 역사를 알면 SSG가 필연적으로 등장할 수밖에 없었음을 알게 됩니다.

#### 1세대: 태초의 웹 (Static)

- **방식:**  1990년대, 개발자는 `index.html`​, `about.html` 파일을 한 땀 한 땀 손으로 짰습니다.
- **장점:**  빠릅니다. 서버는 그냥 파일만 던져주면 됐으니까요.
- **단점:**  100페이지짜리 웹사이트에서 메뉴 하나를 수정하려면, 파일 100개를 다 열어서 고쳐야 했습니다. (노가다의 지옥)

#### 2세대: CMS의 등장 (Dynamic) - 워드프레스의 시대

- **해결책:**  "귀찮게 파일을 다 만들지 말고, 내용은 데이터베이스(DB)에 넣고, 접속할 때마다 기계가 조립해서 보여주자!"
- **방식:**  PHP, JSP, ASP 같은 언어가 등장합니다. 사용자가 접속하면 서버가 그때부터 DB를 뒤져서 HTML을 **즉석에서 요리(Rendering)** 합니다.
- **장점:**  관리가 편합니다.
- **치명적 단점:**

  - **느림:**  접속할 때마다 요리를 새로 해야 합니다.
  - **보안 취약:**  DB 문이 열려 있으니 해커들의 맛집이 되었습니다. (SQL Injection 등)

#### 3세대: SSG의 탄생 (Back to Basic + Automation)

- **철학:**   *"*​*아니, 블로그 글은 한 번 쓰면 잘 안 바꾸잖아? 그럼 매번 접속할 때마다 DB를 뒤져서 렌더링 할 필요가 없이, 글 쓸 때 딱 한 번만 렌더링해서 HTML로 박제해두는게 더 효율적이지 않을까?"*
- **혁신:**  1세대의 '빠름/보안'과 2세대의 '편리함'을 합쳤습니다.

  - 내용은 2세대처럼 편하게 작성(Markdown)합니다.
  - 하지만 서버에 올리기 전에 **SSG라는 기계(Compiler)** ​가 1세대처럼 HTML 파일 수천 개를 **미리 다 만들어버립니다(Pre-rendering).**

---

### 2. 구조적 차이: 컴퓨터 내부를 들여다보자

이해를 돕기 위해 \*\*'식당 주방'\*\*에 비유하고, 실제 \*\*데이터 흐름(Data Flow)\*\*을 비교해보겠습니다.

#### A. 동적 사이트 (Dynamic Site, 예: 워드프레스)

- **비유:**   **'주문 즉시 조리하는 식당'**
- **작동 흐름 (Run-Time Processing):**

  1. 사용자: "1번 글 보여줘" (요청)
  2. 웹 서버: "어? 잠깐만 기다려." -\> (PHP 엔진 깨움)
  3. PHP 엔진: "DB야, 1번 글 내용이랑 작성자 가져와." -\> (SQL 쿼리 전송)
  4. DB: "여기 있어." -\> (데이터 반환)
  5. PHP 엔진: "자, 이제 HTML 템플릿에 데이터 끼워 넣고 비벼보자..." -\> (HTML 생성)
  6. 웹 서버: "자, 여기 HTML." (응답)

  - **문제:**  사용자가 1만 명이면 이 짓을 1만 번 반복합니다. 서버가 터집니다.

#### B. SSG (Static Site Generator, 예: Hugo)

- **비유:**   **'미리 만들어둔 편의점 도시락 공장'**
- **작동 흐름 (Build-Time Processing):**

  1.  **[개발자 컴퓨터]:**  당신이 글(Markdown)을 쓰고 `hugo build` 명령어를 칩니다.
  2.  **[SSG 엔진]:**  글 100개와 디자인 틀(Theme)을 순식간에 결합해서 `index.html`​, `post-1.html`​... 파일 100개를 \*\*미리 생성(Build)\*\*합니다.
  3.  **[서버 업로드]:**  완성된 HTML 파일만 서버에 올립니다.
  4. 사용자: "1번 글 보여줘"
  5. 웹 서버: "어, 여기 파일 있어. 가져가." (끝)

  - **특징:**  서버는 아무런 계산도 하지 않습니다. 그냥 파일만 건네줍니다. 미친 듯이 빠릅니다.

---

### 3. 왜 이름이 "Generator(생성기)"인가?

이 소프트웨어의 본질이 \*\*"원재료(Raw Data)를 넣으면 완제품(Web Page)을 찍어내는 공장 기계"\*\*이기 때문입니다.

- **Input (입력):**

  - 내용: Markdown 파일 (`.md`) - 당신이 SiYuan에서 쓴 글.
  - 디자인: 템플릿 파일 (HTML/CSS 틀).
  - 설정: Config 파일 (사이트 제목, URL 등).
- **Process (생성):**

  - SSG 엔진(Hugo)이 입력값들을 믹서기에 넣고 갈아버립니다.
- **Output (출력):**

  - 순수한 HTML, CSS, JavaScript 파일들. (브라우저가 가장 좋아하는 형태)

---

### 4. 보안 전문가 관점: 왜 SSG인가?

당신이 가장 중요하게 생각할 부분입니다.

1. **DB가 없다 (Database-less):**  해커가 털고 싶어도 털 데이터베이스가 존재하지 않습니다. SQL Injection 공격 자체가 성립하지 않습니다.
2. **읽기 전용 (Read-Only):**  서버에 있는 파일은 그냥 텍스트 파일입니다. 해커가 웹사이트를 통해 악성 코드를 심거나 데이터를 변조할 '실행 권한'이 없습니다.
3. **DDoS 방어:**  HTML 파일은 용량이 매우 작습니다. 트래픽 공격이 들어와도 서버(GitHub Pages나 CDN)가 웃으면서 받아낼 수 있습니다.

### 요약

**SSG**는 웹사이트를 \*\*"프로그램(동적)"\*\*으로 운영하는 게 아니라, \*\*"문서(정적)"\*\*로 만들어서 배포하는 기술입니다.

- **과거:**  손으로 HTML을 짰음. (힘듦)
- **현재(SSG):**  기계(Hugo)가 나 대신 HTML을 짜줌. (편함 + 빠름 + 안전함)
